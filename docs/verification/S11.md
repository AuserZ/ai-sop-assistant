## Implemented changes (concise)

- **n8n Queue Mode chat orchestration (`n8n/s11-chat.v1.json`, `infra/n8n/bootstrap.mjs`, `docker-compose.yml`, `infra/storage-fixture/compose.yml`, `tests/workflows/chat-contract.ts`, `tests/unit/chat-workflow.test.ts`):** Added `sop-s11-chat-v1` with 17-claim RS256 dispatch verification, staged RS256-signed callbacks (`claim` -> `retrieve` -> `generate` -> `validate`, plus `continueErrorOutput` -> `fail`) with empty `{}` payloads (zero SOP passages or candidate drafts in n8n/Redis), `terminal === true` short-circuits, `followRedirects: false`, zero saved execution data, bootstrap import/publish registration, and Compose wiring.
- **Database schema & migration (`drizzle/0007_chat_conversations.sql`, `drizzle/meta/0007_snapshot.json`, `drizzle/meta/_journal.json`, `src/server/db/schema.ts`):** Added `app.chat_conversations`, `app.chat_messages` (`UNIQUE (owner_id, request_key, role)`, `CHECK`s blocking unvalidated drafts and enforcing exact `No SOP found for this question` on `NO_EVIDENCE`, trigger `enforce_chat_message_owner`), `app.chat_message_sources` (`UNIQUE (message_id, chunk_id)`, survives `sop_chunks` deletion so historical citations resolve unavailable, trigger `enforce_chat_message_source_passed`), and private `app.chat_turn_artifacts` (deleted on terminal commit/fail/reconcile). Extended `workflow_jobs`/`workflow_events` for `chat_turn` and applied least-privilege `sop_runtime` grants (`REVOKE UPDATE` on messages/sources; zero `sop_n8n` access).
- **Safe SSE, internal stage callbacks & reconciliation (`src/server/jobs/*`, `src/server/chat/*`, `src/app/api/chat/**`, `src/app/api/internal/chat/**`):**
  - `POST /api/chat/messages` enforces active user, CSRF, 16 KB body cap, `chat:send` rate limit, `(ownerId, requestKey)` idempotency (`409` on hash mismatch), and streams Next.js-owned SSE (`X-Accel-Buffering: no`, `Cache-Control: no-store, no-transform`) or `202` JSON; `GET /api/chat/jobs/[id]/events` supports `Last-Event-ID` replay, `65_536`B backpressure budget, heartbeat, and `stream_timeout`.
  - Byte-level stream safety: `serializeChatEvent` emits only allowlisted progress (`accepted`, `retrieving`, `reranking`, `generating`, `validating`) before deterministic checks, independent judge, live citation eligibility, and live user checks pass; `chat_turn_artifacts` is never queried by SSE. Live source/user rechecks on `validate` AND on SSE `completed` emission withhold answers if a source is deleted (`no_evidence` with `sources: []`) or user is deactivated (`401`).
  - `GET /api/chat/conversations` and `GET /api/chat/conversations/[id]` enforce owner-only access (`404` cross-user) and recheck live S08 citation availability (`UNAVAILABLE` for Staff, `DELETED` for Admin).
- **Chat UI, SafeMarkdown, docs & tests (`src/app/chat/page.tsx`, `src/components/chat/*`, `src/components/auth/session-status.tsx`, `docs/{api-contracts,database,n8n-workflows}.md`, `tests/{unit,integration,e2e}/chat.*`):** Built XSS-safe `SafeMarkdown` (zero `dangerouslySetInnerHTML`/raw HTML/external links), `ChatWorkspace` with current-session persistence (`?c=`/`sessionStorage`, no P1 C7 reopen sidebar), live stage status, `Last-Event-ID` reconnect, clickable backend-authorized citations / `"Source unavailable"` badges, exact fallback & safe retryable error state, separate `data-first-progress-ms`/`data-first-answer-ms`/`data-completed-ms` attributes, `320px` zero-overflow, `<= 3` menus, and unit/DB/Playwright suites.
