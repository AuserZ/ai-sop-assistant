## Implemented changes (concise)

- **Retrieval contracts & fail-closed config (`src/server/retrieval/{contracts,config,index}.ts`):** Defined strict Zod schemas, PRD tunable defaults (`semanticTopK: 15`, `keywordTopK: 15`, `finalTopK: 5`, `rrfK: 60`, `historyMaxTurns: 8`, `minRerankScore: 0.15`), exact fallback constant `No SOP found for this question`, and typed `RetrievalError` codes strictly separate from `no_evidence`. Live OpenAI mode requires explicit `OPENAI_RERANKER_MODEL` / `OPENAI_REWRITE_MODEL` and `OPENAI_API_KEY`, explicitly rejecting unverified `"GPT-6 Luna"` placeholder variants (`/gpt[-_.\s]?6[-_.\s]?luna/i`); fixture mode and `OPENAI_BASE_URL` overrides are strictly loopback-gated.
- **Dual ACTIVE-only SQL search & post-rerank reload (`src/server/retrieval/search.ts`):** Shared `activeChunkEligibilityPredicate()` enforces `status = 'ACTIVE'`, non-null active/verified bindings, and exact `job_id`/`pipeline_version`/`source_sha256` match INSIDE BOTH `searchSemanticActiveChunks` (1,536-dim validation + schema-qualified `OPERATOR(public.<=>)`) and `searchKeywordActiveChunks` (safe alphanumeric lexeme-OR `to_tsquery('simple', ...)` + `ts_rank_cd`) BEFORE `ORDER BY` and `LIMIT`. `loadOriginalActivePassagesByIds` reloads unchanged DB rows in reranked order while re-verifying `ACTIVE` status, snapshot identity, and `contentHash` (excluding mid-flight deleted/reprocessed chunks).
- **RRF, strict ID-only reranker, bounded follow-up rewriter & orchestration (`src/server/retrieval/{rrf,rerank,rewrite,service}.ts`):**
  - `fuseHybridCandidates` computes `1/(rrfK + rank)` with exact snapshot identity deduplication and fail-closed `RETRIEVAL_IDENTITY_CONFLICT` on hash/snapshot mismatch.
  - `rerankCandidateIds` fences untrusted candidates (`<` escaped as `\u003c`), validates strict JSON IDs/finite `[0, 1]` scores, fails closed (`502 RETRIEVAL_RERANKER_INVALID_OUTPUT`) on unknown/duplicate/mutated/malformed output, separates body-read/network aborts (`503 RETRIEVAL_PROVIDER_TRANSIENT`) from schema errors, and supports deterministic injection-immune `synthetic_fixture` mode.
  - `rewriteRetrievalQuery` bounds history turns/chars as query-rewrite input only (never evidence), neutralizes prompt injection, and shortcuts empty history without external calls.
  - `retrieveActiveSopEvidence` / `retrieveActiveSopEvidenceForAccount` enforce pre- and post-retrieval `lockCurrentUser`, reuse `embedTexts` (mapping embedding outages to `RetrievalError`, never `no_evidence`), emit discriminated `evidence` vs `no_evidence` (`NO_CANDIDATES` | `WEAK_EVIDENCE` | `ELIGIBILITY_REVOKED`) with 8 stage timings, and log zero SOP passages/prompts/secrets.
- **50-question synthetic benchmark, rubric & tests (`tests/fixtures/benchmark-50.json`, `docs/benchmarks/rag-benchmark-rubric.md`, `tests/unit/{retrieval,benchmark-dataset}.test.ts`, `tests/integration/retrieval.test.ts`):** Added versioned `v1.0.0` 50-question synthetic SOP benchmark covering all 11 PRD Section 14 categories, proposed rubric/latency doc preserving PRD Section 16 open gates, `19` new unit tests, and real PostgreSQL/pgvector integration tests for both branches' trap exclusion, delete/reprocess races, and deactivated user denial.
