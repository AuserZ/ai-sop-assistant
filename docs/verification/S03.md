## Historical failures and verified fixes

1. A partial injected environment in unit tests initially conflicted with inferred `NodeJS.ProcessEnv`, whose Next.js typing requires `NODE_ENV`. Explicit read-only string/undefined environment types fixed the typecheck. Unit/types then passed.
2. External task-runner mode requires a dedicated auth token even for this code-free graph. DevOps added a separate n8n-only token file; actual worker startup now passes without enabling Code or adding a runner sidecar.
3. An optional upstream catalogue module attempted external DNS and was blocked by the internal network. Exact-tag supported module configuration now disables that unneeded module. This is not reported as an external call succeeding or as proof that every future n8n node has no egress.
4. Baseline database failure: nonce cleanup selected `FOR UPDATE` while UPDATE privilege is intentionally revoked on immutable nonce receipts. Removing that unnecessary lock preserved permissions; actual corrected database tests and browser dispatch now PASS.
5. Baseline database failure: a stream test assumed its first chunk contained `started`; a valid first chunk can contain only `accepted`. Reading to the semantic event boundary retained the assertion; actual corrected database suite PASS.
6. Pressure regressions demonstrated repeated polling while blocked, heartbeat budget overflow and a full queue outliving its deadline. The fix enforces all frame budgets, stops blocked polling and closes independently at the hard deadline. Seven targeted native WebStream regressions PASS; their mocked storage/clock limits remain explicit.
7. Independent security review found omitted redirect configuration in all five native HTTP Request nodes. Explicit `options.redirect.redirect.followRedirects=false`, export assertions, actual republished graph inspection and native method-matched POST controls PASS. No actual credential leak was demonstrated.
8. The read-only proxy initially failed because nginx default upstream temp paths targeted its read-only root. Moving the three paths into its existing private `/tmp` tmpfs fixed startup without broadening filesystem permissions; health and browser tests PASS.
9. QA found false-pass and cleanup gaps in the host fault verifier: mutations outside recovery protection, uncancelled collectors, permissive wire parsing and early return at the first terminal frame. The lead added scoped restoration, strict framing/DTO/cursor/deadline checks and clean-EOF validation. QA's eight isolated collector and five cleanup/deadline cases PASS; all six actual runtime cases then PASS. These findings concern verification tooling; no corresponding backend data leak was observed.
10. The first runtime run failed its deactivation check while service restoration observed a briefly unhealthy worker; outer cleanup recovered it. The verifier now starts the owned service and polls actual health within 90s, allowing recovery from transient unhealthy state while rejecting dead/exited services or a deadline failure. The final live deactivation case passes, with stream closure and HTTP401 afterward.
11. Execution-storage inspection found an abandoned running row containing a short-lived JWT. Native pruning excludes running rows, and the pinned queue-recovery default is 180 minutes. The supported local recovery interval is now one minute. Startup recovery marked the row crashed; during the six actual faults, crashed rows increased from one to two with the same main container/start time/restart count, proving periodic recovery. At 13:21:55Z on 20 November, eleven terminal payload rows still contained 45 JWT occurrences; nine rows were soft-deleted. At 01:41:58Z on 21 November, unchanged normal native settings had removed all probe execution entities and payloads: direct payload/JWT/orphan counts were zero. Redis jobs/JWTs and Docker/native log markers were also zero. No accelerated pruning experiment, configuration override or direct table write occurred. Save-none settings alone do not establish immediate deletion.
